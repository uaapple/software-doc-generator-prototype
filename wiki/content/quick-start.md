# 快速开始

这页从零开始走一遍：先创建工程，再创建功能模块，确认是否复用已有 Module Skill，最后进入软件需求生成页发起第一次任务。

![工程列表入口](/assets/quick-start/01-project-list.png)

## 先记住 6 个概念

- `工程`：平台里的最高层容器，用来归纳一个业务范围或项目范围。
- `功能模块`：工程下的工作单元。不同模块可以有各自的输入资产、生成任务和已采纳结果。
- `Module Skill`：针对某个功能模块沉淀的模块级写作能力。交付版本的技能库里如果已经包含对应模块，可以在创建模块时直接绑定。
- `技能冷启动`：当没有可复用 Module Skill 时，系统会在首次软件需求生成前先根据系统需求、模型/代码输入和优秀范例提炼模块能力。
- `模块资产`：当前模块下可参与生成的输入文件，包括系统需求、模型资料、生成代码和参考样例。
- `生成任务`：你在某个文档类型空间里发起的一次生成动作。任务会保留输入、执行进度、结果和审核信息。
- `已采纳结果`：生成结果经过人工确认后沉淀下来的内容，用来代表当前模块在该文档类型下的阶段性成果。

## Step 1：创建工程

从工程列表点击 `创建工程`。工程名称建议用业务域或交付项目名，例如 `VCU`、`车身域控制器`、`热管理平台`。工程描述可以先简写，后续仍可编辑。

![创建工程表单](/assets/quick-start/02-create-project.png)

创建完成后，进入工程详情页。这个页面负责承载多个功能模块，不建议把所有输入文件都堆在工程层面直接生成。

## Step 2：创建功能模块

在工程页点击 `创建功能模块`。模块名称建议贴近真实功能边界，例如 `扭矩干预`、`充电管理`、`低压能量管理`。系统会根据模块名称推荐 domain，并检索是否存在可复用的 Module Skill。

![创建功能模块表单](/assets/quick-start/03-create-module-empty.png)

## Step 3：选择 Module Skill 或冷启动

如果候选列表里出现匹配的 Module Skill，优先选择 `绑定已有 Module Skill`。交付版本的技能库会预置部分功能模块的 Module Skill，这种情况下模块可以直接复用已有模块层能力，不需要先做技能冷启动。

![Module Skill 候选与冷启动模式](/assets/quick-start/04-module-skill-candidates.png)

如果没有合适候选，选择 `冷启动`。冷启动不是失败路径，而是第一次为这个模块建立专属写作能力。进入软件需求生成前，至少要准备系统需求文件、模型或代码输入，以及一份同类型的人工优秀范例。

## Step 4：进入模块工作区

模块创建后会进入模块工作区。这里可以查看已采纳结果、文档提取、软件需求生成、详细设计生成、HIL 用例生成和模块反馈池。

![模块工作区](/assets/quick-start/05-module-workspace.png)

第一次使用时，先确认模块资产是否齐全。生成页面只使用当前模块上下文，不会自动读取其他模块的文件。

## Step 5：进入软件需求生成

在模块工作区点击 `进入软件需求生成`。页面会展示当前模块可用的资产、历史任务和生成入口。选择本次要参与生成的资产，必要时补充上传新文件。

![软件需求生成入口](/assets/quick-start/06-requirement-generation.png)

如果模块已经绑定已有 Module Skill，可以直接开始生成。如果模块处于冷启动模式，系统会先引导完成一次技能冷启动，再继续正式的软件需求生成任务。

## Step 6：等待任务并查看结果

任务启动后，可以从 `历史任务` 或任务队列进入详情。完成后，任务详情会显示执行进度、Agent 运行日志、输入资产数、生成模型和结果数量。

![历史任务列表](/assets/quick-start/07-task-history.png)

![生成任务详情](/assets/quick-start/08-task-detail.png)

查看结果时，先判断结果是否覆盖核心主题，再逐条确认来源依据、验证提示和冲突提示。可以直接采纳质量稳定的条目；有问题的条目建议用结构化驳回进入反馈池，后续可通过 Replay / Fallback 修正。

## 初次使用最容易忽略的点

- 生成页面依赖的是“当前模块上下文”，不是整个工程的全量文件池。
- 补充上传的文件会先进入当前模块资产，再参与本次任务。
- 有 Module Skill 候选时可以直接绑定，不必为了“初始化完整”而强行冷启动。
- 冷启动需要优秀范例参与，否则模块级写作能力很难稳定沉淀。
- 驳回不是简单删除，而是会沉淀成后续可回投、可修正的反馈记录。

## 结果怎么看

第一次使用时，不要急着追求“最终文档”。先确认下面三件事：

- 结果是否覆盖了你关心的主要主题
- 每条结果是否带着清晰的来源依据
- 哪些条目可以直接采纳，哪些条目需要驳回或后续修正
