# 反例

1. 软件应合理处理扭矩干预请求。
问题：没有写明对象、触发条件、优先级和输出结果，无法验证。

2. 当前后轴有请求时，系统按情况处理。
问题：缺少章节归属、条件分支和对称对象拆分，“按情况”属于模糊措辞。

3. 软件应根据需要限制输出扭矩。
问题：没有说明最大/最小限制、变量名、条件和来源依据。

4. 当功能激活时，输出标志位。
问题：没有说明哪一个功能、哪个标志位以及输出状态值。

5. 参考其他需求即可。
问题：引用不完整，没有给出具体需求编号，也缺少当前需求自身的行为描述。

6. ESC前后轴扭矩干预激活标志位根据对应轴请求综合判断。
问题：把前轴和后轴合并成一条，丢失了目标样例要求的对称拆分和对象级信号命名。

7. 软件应提供接口定义、时序要求、诊断要求和越野模式处理。
问题：这些条目本身未必错误，但若当前目标样例的核心结构还没写出来，先输出这类泛化条目会让结果偏离人工设计文档。
